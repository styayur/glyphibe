## Kando: interaction reference, not an analysis engine

[package.json](https://github.com/kando-menu/kando/blob/d860e24da203f8969872f62846fad5a6a859e522/package.json) identifies an Electron/TypeScript application with React settings UI, native CMake addons and Electron Forge packaging. [menu-window.ts](https://github.com/kando-menu/kando/blob/d860e24da203f8969872f62846fad5a6a859e522/src/main/menu-window.ts) implements a transparent, frameless, initially hidden full-screen overlay. It tracks visible state, waits for renderer readiness, maps pointer coordinates through zoom and handles per-monitor Windows DPI changes. Its renderer uses sandboxing and context isolation. These are useful interaction lessons for collapsible tool islands, focus restoration and high-DPI testing. Glyphibe should implement its own state model and retain a normal resizable application window.

Kando contains actions to execute commands and manipulate the desktop. Those capabilities are outside Glyphibe's analysis trust boundary and must not be adopted. Kando is not a code indexer: call resolution, clustering, cross-language relations and incremental source indexing are not applicable. No LLM is needed for its menu mechanics. No measured Glyphibe rendering or memory benefit follows from this inspection.

[LICENSE.md](https://github.com/kando-menu/kando/blob/d860e24da203f8969872f62846fad5a6a859e522/LICENSE.md) states that source is MIT while assets, configuration and documentation can use other licenses. The project follows REUSE with per-file SPDX or adjacent license files; its LICENSES directory includes MIT, CC-BY-4.0, CC0-1.0, OFL-1.1 and a Pixabay license reference. A GitHub NOASSERTION summary therefore must not be interpreted as a blanket license. Glyphibe will reference interaction ideas without importing its assets or implementation.

## Tauri: one Rust host, a constrained frontend

The inspected [workspace manifest](https://github.com/tauri-apps/tauri/blob/7e39750cf6a4e05234a781088ff5fb8cb890370a/Cargo.toml) specifies Rust 1.90 and `Apache-2.0 OR MIT`. [tauri/Cargo.toml](https://github.com/tauri-apps/tauri/blob/7e39750cf6a4e05234a781088ff5fb8cb890370a/crates/tauri/Cargo.toml) exposes the separation between host, runtime, macros and bundler; platform dependencies include Windows WebView2, Linux GTK/WebKit and macOS WebKit/AppKit. This supports an in-process Rust analysis core, with GUI commands calling the same library as CLI and MCP. It does not require a second indexer or an HTTP service. Neither the host nor WebView supplies semantic analysis automatically.

Tauri's [capability documentation](https://v2.tauri.app/security/capabilities/) defines grants per window/webview and warns that overlapping grants combine. Registered application commands are available by default unless an application command manifest constrains them. Glyphibe therefore needs explicit command permissions, validated repository handles, narrowly scoped source retrieval, no frontend shell plugin, no remote-content IPC grants and a restrictive Content Security Policy. Rust commands must still validate paths; permissions are not a substitute for filesystem containment checks. Imported documentation is data, never executable instructions.

[Windows packaging documentation](https://v2.tauri.app/distribute/windows-installer/) describes WiX MSI and NSIS EXE installers. MSI creation requires Windows; the MSVC target is the supported Windows toolchain. WebView2 provisioning choices include downloading, embedding the bootstrapper, an offline installer or a fixed runtime. An offline core does not imply that a fresh machine without WebView2 can install an installer that downloads its runtime while disconnected. Packaging decisions and documented prerequisites must match the actual tested artifact. MSI also has a documented VBScript optional-feature prerequisite. Build success cannot substitute for install, launch, reopen, upgrade, uninstall and reinstall tests. No signing certificate was inspected, so signed distribution and suppression of SmartScreen warnings cannot be claimed.

Tauri's system WebView may reduce the need to ship a browser runtime, but package size, resident memory, startup time and graph throughput must be measured on Glyphibe. No numerical desktop performance result is established here. Cross-platform dependencies are evidence of upstream support, not of Glyphibe validation.

## window-vibrancy: Mica with fallible fallback

The inspected [Cargo.toml](https://github.com/tauri-apps/window-vibrancy/blob/c93f682aa957560d778ca903a881b7c5ba0eb5b9/Cargo.toml) specifies `Apache-2.0 OR MIT`, Rust 1.77 and raw-window-handle 0.6. [windows.rs](https://github.com/tauri-apps/window-vibrancy/blob/c93f682aa957560d778ca903a881b7c5ba0eb5b9/src/windows.rs) calls native DWM attributes and checks operating-system builds. Mica uses the system-backdrop path from build 22523, with an older Windows 11 path from build 22000; unsupported versions and failed DWM calls can return errors. Handle failure without panicking, retain legible opaque panels and let users disable transparency. Native window material and CSS panel backdrop filtering solve different visual layers.

The [README](https://github.com/tauri-apps/window-vibrancy/blob/c93f682aa957560d778ca903a881b7c5ba0eb5b9/README.md) documents blur/acrylic resize/drag performance problems on certain Windows builds and no Linux implementation. Accordingly, prefer Mica on supported Windows 11, use restrained local glass panels, and offer an opaque reduced-effects mode. Do not repeatedly reapply native effects in a graph animation loop. Upstream warnings do not quantify Glyphibe's cost: actual GPU, window resizing and high-DPI tests remain required.

## MCP: use the official SDK and test both lifecycle eras

The inspected [SDK README](https://github.com/modelcontextprotocol/rust-sdk/blob/cd88056ffdc97756fbd98e5a12bbeb41758f0ce8/README.md) and [protocol model](https://github.com/modelcontextprotocol/rust-sdk/blob/cd88056ffdc97756fbd98e5a12bbeb41758f0ce8/crates/rmcp/src/model.rs) support stable `2026-07-28` and legacy `2025-11-25` and earlier revisions. This distinction matters: the newer protocol uses discovery and per-request metadata, while legacy clients use initialize/initialized. The official [transport specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports) defines newline-delimited JSON-RPC over stdio. Use rmcp's stdio transport and lifecycle handling rather than a handwritten JSON-RPC loop. Put logs only on stderr; stdout carries protocol messages. Validate a real client against list-tools, successful calls, invalid arguments, cancellation and clean EOF shutdown.

[rmcp/Cargo.toml](https://github.com/modelcontextprotocol/rust-sdk/blob/cd88056ffdc97756fbd98e5a12bbeb41758f0ce8/crates/rmcp/Cargo.toml) supports server, macros, schemars and transport-io features. Restrict the feature set to local stdio needs and keep transport independent of core queries. An allowlisted analyzed root and separate proposal store must guard writes; a tool must not accept an arbitrary shell command or upgrade Proposed evidence into Observed facts.

The SDK's [LICENSE](https://github.com/modelcontextprotocol/rust-sdk/blob/cd88056ffdc97756fbd98e5a12bbeb41758f0ce8/LICENSE) documents a transition: new code/specification contributions are Apache-2.0, some earlier un-relicensed contributions remain MIT, and non-spec documentation is CC-BY-4.0. Its manifest alone is insufficient for release notices. Preserve both applicable code notices from the actual shipped package and do not copy documentation into the knowledge bundle.

## Tree-sitter: syntax facts, not whole-program certainty

The official [parser guide](https://tree-sitter.github.io/tree-sitter/using-parsers/) and [Rust binding](https://github.com/tree-sitter/tree-sitter/blob/dfe770858e3cfd8e8b29a79ea17da390a6f60319/lib/binding_rust/lib.rs) expose syntax trees with byte/range positions, edit-based tree reuse and changed ranges. The binding also exposes ParseOptions progress callbacks for cancellation. Parser/grammar ABI acceptance must be checked through `set_language` and language tests. Use one parse per changed file, retain content hashes and file extraction results, and rebuild affected relations separately. Full re-resolution or reclustering can be an explicit strategy where a safe incremental algorithm is not yet implemented.

[Python bindings](https://github.com/tree-sitter/tree-sitter-python/blob/26855eabccb19c6abf499fbc5b8dc7cc9ab8bc64/bindings/rust/lib.rs) expose LANGUAGE; [TypeScript bindings](https://github.com/tree-sitter/tree-sitter-typescript/blob/75b3874edb2dc714fb1fd77a32013d0f8699989f/bindings/rust/lib.rs) expose separate TypeScript and TSX constants. The parser and four grammar repositories use MIT licenses. Depend on published crates with locked checksums and preserve their licenses. Grammar-generated native code is compiled as a trusted dependency, never regenerated or executed from an analyzed repository.

Syntax trees provide declared symbols, scopes and syntactic call expressions. They do not establish receiver types, dynamic dispatch, reflection, Python import side effects, macro expansion or cross-language runtime bindings. Implement conservative language-specific name/import resolution, record ambiguous/dynamic calls explicitly and label inferred edges. Do not claim whole-program call completeness from parsing alone. Parse-error recovery must be reported in graph diagnostics rather than silently treated as complete facts. Large-file size/time limits and bounded concurrency are still application responsibilities.

## Decision guidance and remaining evidence

Proceed with a shared Rust core, official grammar crates, rmcp stdio and Tauri 2. Native Mica is optional and fallible; the opaque fallback is a first-class operating mode. Keep Electron/Kando as an interaction reference only. All inspected licenses permit a plausible dependency path for an MPL-2.0 application, subject to package-level transitive audits, attribution and source-distribution obligations. This is an engineering compatibility assessment, not a claim that the final dependency graph has been audited.

Still unverified: Glyphibe's actual native build, feature-specific ABI compatibility, per-command capability isolation, installer lifecycle, signing state, actual client interoperability, operating-system fallback behavior, memory and frame rate. Those are release gates and cannot be inferred from upstream source.
