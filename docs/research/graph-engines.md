## GitDiagram

The current application combines GitHub repository trees, README excerpts and ranked source excerpts with model-produced architecture graphs. Its deterministic reference reader supports several language families with text matching and file resolution; these references can support edge citations. That is useful provenance, but does not establish exact function-call semantics. The graph planner calls structured model generation and validates output against a schema and known paths. Removing model generation leaves useful repository ingestion and validation, not the same architecture inference product. [Source reference reader](https://github.com/ahmedkhaleel2004/gitdiagram/blob/7d3bc546d370ac789eefd59676a3c6d30c8ce78b/src/server/generate/source-references.ts), [planner](https://github.com/ahmedkhaleel2004/gitdiagram/blob/7d3bc546d370ac789eefd59676a3c6d30c8ce78b/src/server/generate/graph-planner.ts), [validator](https://github.com/ahmedkhaleel2004/gitdiagram/blob/7d3bc546d370ac789eefd59676a3c6d30c8ce78b/src/server/generate/graph.ts).

The diagram schema has groups, nodes and directed edges, including repository/evidence paths, with limits of 10 groups, 34 nodes and 48 edges. It is a compact summary representation, not a 10,000-symbol analysis graph. Repository ingestion tracks blob SHA/size, bounded tree caching and truncated trees; context ranking limits input. These are bounded ingestion measures, not demonstrated incremental AST indexing. [Graph schema](https://github.com/ahmedkhaleel2004/gitdiagram/blob/7d3bc546d370ac789eefd59676a3c6d30c8ce78b/src/features/diagram/graph.ts), [GitHub ingestion](https://github.com/ahmedkhaleel2004/gitdiagram/blob/7d3bc546d370ac789eefd59676a3c6d30c8ce78b/src/server/generate/github.ts), [context selection](https://github.com/ahmedkhaleel2004/gitdiagram/blob/7d3bc546d370ac789eefd59676a3c6d30c8ce78b/src/server/generate/repository-context.ts).

Glyphibe should independently implement source evidence and strict graph validation, while keeping semantic proposals separate from observed facts. No GitDiagram benchmark or model accuracy result is adopted as Glyphibe evidence.

## Sigma.js

Sigma consumes a Graphology-compatible graph rather than discovering source symbols. The reviewed current implementation uses WebGL2, GPU node/edge data textures, framebuffer picking and scheduled rendering. Its label renderer reuses GPU buffers when labels are unchanged and selects label candidates through a density-controlled label grid. These mechanisms suit Dense, local Frontier and aggregated Cluster views without creating a React DOM component for every symbol. [Renderer](https://github.com/jacomyal/sigma.js/blob/40dc474a04218ef36df6b4de8d2ee05eb78ba3ec/packages/sigma/src/sigma.ts), [labels](https://github.com/jacomyal/sigma.js/blob/40dc474a04218ef36df6b4de8d2ee05eb78ba3ec/packages/sigma/src/core/label-renderer.ts), [manifest](https://github.com/jacomyal/sigma.js/blob/40dc474a04218ef36df6b4de8d2ee05eb78ba3ec/packages/sigma/package.json).

Graph attributes can carry display state, but repository revisions, evidence classes, invalidation and dual-plane semantics remain Glyphibe responsibilities. Sigma supplies no parser, call resolver, business-component inference or LLM requirement. A separate layout algorithm is still needed. Its advertised purpose includes graphs with thousands of entities; that is not a hardware-specific frame-rate guarantee. GPU context recovery in the inspected source does not prove WebView2 driver compatibility on every machine. Glyphibe must measure frame intervals and interaction latency with real rendering, record graph size and GPU, and verify degradation when WebGL2 is unavailable.

## React Flow

React Flow is an interactive node-editor library. It renders node wrappers and edge wrappers, with memoization, fine-grained subscriptions and optional visibility filtering. The source explicitly explains avoiding repeated expensive node-list rendering during dragging. Rich React nodes are appropriate for bounded component diagrams, but permanently rendering every function this way would put UI complexity on the hot path. [Node renderer](https://github.com/xyflow/xyflow/blob/bb63f4cc345acf4e6c73e0371be3ea3ca01b2a18/packages/react/src/container/NodeRenderer/index.tsx), [edge renderer](https://github.com/xyflow/xyflow/blob/bb63f4cc345acf4e6c73e0371be3ea3ca01b2a18/packages/react/src/container/EdgeRenderer/index.tsx).

Official guidance recommends stable component/callback identities, narrower state subscriptions, collapsing node groups and simpler styling. None establishes a universal 5,000-node FPS number. [Performance guidance](https://reactflow.dev/learn/advanced-use/performance). Its graph editing state does not substitute for the persistent code graph. It has no code indexer, automatic AST semantics, six-level mapping or required LLM. The repository package is MIT; paid Pro offerings are separate and should not be presumed licensed by that file. [Package manifest](https://github.com/xyflow/xyflow/blob/bb63f4cc345acf4e6c73e0371be3ea3ca01b2a18/packages/react/package.json).

## react-force-graph

This library provides common-interface bindings to 2D Canvas and 3D Three.js/WebGL graph renderers; it is not a source analyzer. Data consists of node/link arrays. The 3D adapter exposes camera positioning, zoom-to-fit, animation pause/resume and force controls. Click handlers, force-engine selection, warm-up and cooldown controls are declared in shared property definitions. These support a real orbitable and selectable Galaxy view, with Glyphibe imposing a node cap and avoiding continuous simulation after settling. [README](https://github.com/vasturiano/react-force-graph/blob/8c301c7a05b22c489b5724301bec52911b51d966/README.md), [3D adapter](https://github.com/vasturiano/react-force-graph/blob/8c301c7a05b22c489b5724301bec52911b51d966/src/packages/react-force-graph-3d/index.js), [properties](https://github.com/vasturiano/react-force-graph/blob/8c301c7a05b22c489b5724301bec52911b51d966/src/forcegraph-proptypes.js).

No LLM is required. Sharing its presentation interface does not automatically synchronize selections, source mappings or analysis parameters; those belong in the application store. Physics, node meshes, labels and link detail can consume substantial CPU/GPU resources. The repository's demonstrations are not measurements of Glyphibe on its shipping WebView. Prefer the standalone 3D package to avoid unnecessary AR/VR dependencies. Audit the resolved Three.js and force-engine dependencies separately. [3D package](https://github.com/vasturiano/react-force-graph/blob/8c301c7a05b22c489b5724301bec52911b51d966/src/packages/react-force-graph-3d/package.json).

## Excalidraw

Excalidraw is a drawing-scene editor with shapes, bindings, text and application state. Rendering uses Canvas2D/RoughJS; current source separates static and interactive scenes and memoizes visibility computations. It is suitable for deliberate human-authored diagrams and export, rather than the primary rendering engine for a large semantic dependency network. [Static rendering](https://github.com/excalidraw/excalidraw/blob/b7de45e88111f5680ae4bb3c3f3541c7d3b279fe/packages/excalidraw/renderer/staticScene.ts), [visibility renderer](https://github.com/excalidraw/excalidraw/blob/b7de45e88111f5680ae4bb3c3f3541c7d3b279fe/packages/excalidraw/scene/Renderer.ts), [manifest](https://github.com/excalidraw/excalidraw/blob/b7de45e88111f5680ae4bb3c3f3541c7d3b279fe/packages/excalidraw/package.json).

Its public API offers initial scene data, change callbacks, themes, zen mode and per-element custom data. These can associate drawing elements with external semantic IDs but do not supply deterministic parsing, call graphs or provenance rules. [API](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/props/). Basic canvas operation has no LLM requirement; optional generation plugins accept external callbacks and do not make an analyzer available. No numerical performance result was established in this audit. Embedding its whole drawing UI would add overlap to Glyphibe's graph-first controls; retain the interaction lessons without integrating a second scene model into the core.

## Engineering recommendation

Use one Rust analysis graph and one serialized graph contract. Frontend projection adapters must preserve canonical node IDs and evidence references. Sigma/Graphology can serve all three 2D modes through different filtering, aggregation and layout policies; a standalone force-graph 3D adapter can serve Galaxy. All four modes should use the same selection/filter/granularity/impact store. Rendering libraries must never own an independent source index.

React Flow remains an optional future bounded component editor, with a separate ADR required before adding it. Excalidraw is unnecessary for the required product. This reduces renderer and state duplication while preserving actual 3D. Native graph state should distinguish observed relations, inferred communities and proposed human/Agent mappings; renderer attributes alone cannot enforce these distinctions.

Pin the actual selected releases and lock transitive dependencies. Current upstream default branches are evidence for this audit, not an instruction to depend on unreleased APIs. Measure 1,000/5,000/10,000-node projections, label density, camera movement, node selection and state transitions independently of analysis throughput. Until those runs exist, all Glyphibe FPS, peak memory and scale targets remain unverified.
