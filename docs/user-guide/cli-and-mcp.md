# CLI and MCP

Queries read the external SQLite index generated by `analyze`. Use `--repo PATH`
and optionally `--index PATH`; an index inside a scanned root is rejected.
Default indexes are per canonical repository in the user cache directory.

```sh
glyphibe analyze path/to/repository
glyphibe --repo path/to/repository search calculate
glyphibe --repo path/to/repository graph --level 5 --plane architecture --limit 500
glyphibe --repo path/to/repository trace NODE_ID --direction downstream --hops 4
glyphibe --repo path/to/repository impact NODE_ID --direction upstream --hops 3
glyphibe --repo path/to/repository explain NODE_ID --depth 1 --language zh
glyphibe --repo path/to/repository map NODE_ID
glyphibe --repo path/to/repository map NODE_ID --ancestors
glyphibe --repo path/to/repository export --output graph.json
glyphibe doctor
```

Use the exact node `id` returned by search/graph. Levels are 1..6, depth is 1..4,
and hops are 0..32. `graph` pages node arrays; `export` emits the full versioned
graph with a node map. `--format dot` exports Graphviz. Existing files require
explicit `--force`. Success exits 0, invalid arguments 2, operation errors 1.
JSON queries use stdout; JSON errors and scan progress use stderr. `--json`
is accepted globally; JSON is already the default. Paths are repository-relative,
lines one-based, and columns are UTF-8 byte columns.

## Agent configuration

Analyze the repository first. A common client configuration is:

```json
{
  "mcpServers": {
    "glyphibe": {
      "command": "glyphibe",
      "args": ["--repo", "/absolute/path/to/repository", "mcp", "serve"]
    }
  }
}
```

Use JSON-escaped Windows paths or forward slashes. The executable must be on
the client's PATH or specified absolutely. Formats differ between clients.
For Codex follow its [official MCP documentation](https://learn.chatgpt.com/docs/extend/mcp?surface=cli):

```toml
[mcp_servers.glyphibe]
command = "glyphibe"
args = ["--repo", "/absolute/path/to/repository", "mcp", "serve"]
```

Glyphibe uses official rmcp 3.8.0 stdio and SDK-generated tool schemas. Tools:
`architecture`, `node`, `search`, `trace`, `impact`, `mappings`, `explain`,
`knowledge`, `proposals`, `propose`. Results include structured JSON. There
is no HTTP port, shell tool or arbitrary source write operation.

The chosen repository/index are the access boundary. `node` returns bounded,
freshness-checked source. Architecture pages contain at most 2,000 nodes.
Static dependency queries omit stale and unaccepted proposed relationships.
Unresolved calls remain diagnostics. SDK client interoperability tests and
external Agent verification are recorded separately in the release ledger.

## Semantic suggestions

`mcp serve --allow-proposals` enables isolated writes. Endpoints must exist;
relations are `depends_on`, cross-plane `maps_to`, and `has_concept` targeting
a concept. Label/rationale lengths are bounded. Proposals carry repository,
revision and Proposed provenance; they cannot replace static facts.

CLI `proposals list` inspects suggestions. `proposals add SOURCE TARGET --label
TEXT --rationale TEXT` stores a dependency-label suggestion. There is no automatic
acceptance of Agent assertions as observed or verified evidence.
